# Trazabilidad de reglas de negocio y decisiones críticas

Cada regla que no se puede romper, con las pruebas automáticas que la sostienen. Las rutas son relativas a `apps/`.
Capas: **BD** = pruebas contra la base de datos (`api/test/bd`), **API** = pruebas de extremo a extremo de la API
(`api/test/*.e2e-spec.ts`), **U** = unitarias, **Flujo** = pruebas de navegador a 360 px y escritorio (`web/e2e/flujos`).

## 1. Reglas de negocio

| #   | Regla                                                                                                       | Pruebas que la comprueban                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | El semáforo indica solo la calidad relativa del precio frente a las opciones visibles y siempre lleva texto | U `api/src/modulos/mapa/semaforo.spec.ts` (punto medio del rango); API `mapa.e2e-spec.ts` «el semáforo llega calculado, con texto…»; «mismo semáforo que la lista para el mismo conjunto»; `confianza.e2e-spec.ts` (calculadora y comparar); Flujo `mapa.spec.ts` «el semáforo del detalle coincide con el de la lista»; `guia.spec.ts` «el semáforo y la demanda se leen con texto»                                                                                                                                    |
| R2  | La demanda es independiente del precio y se muestra con otro estilo                                         | BD `precios.spec.ts` «la demanda cambia sin tocar el precio ni generar historial» y «solo admite Alta, Media o Baja»; API `negocios.e2e-spec.ts` «…precio y demanda guardados por separado»; Flujo `guia.spec.ts`                                                                                                                                                                                                                                                                                                       |
| R3  | El precio por material es un rango obligatorio, gestionado solo por el centro o comprador                   | BD `precios.spec.ts` «el rango es obligatorio», «el mínimo no puede superar al máximo», «acepta los límites exactos»; API `negocios.e2e-spec.ts` «rechaza precios fuera de S/ 0.10 a S/ 50.00…»; `mapa.e2e-spec.ts` «guardar cambia el precio, deja historial y valida el rango»                                                                                                                                                                                                                                        |
| R4  | La administración puede moderar o marcar precios, pero no modificarlos                                      | BD `plan.spec.ts` «la administración solo escribe el plan y sus fechas: ni… los precios del negocio»; `permisos.spec.ts`; Flujo `confianza.spec.ts` «el administrador… suspende un precio sin poder editarlo»                                                                                                                                                                                                                                                                                                           |
| R5  | La ubicación exacta del reciclador nunca se expone ni sale del servidor                                     | BD `publicaciones.spec.ts` «la API sigue sin poder leer la ubicación de una publicación» y «ya no existe una función para copiar la ubicación»; `endurecimiento.spec.ts` (`ubicaciones_propias`: ataque); `tramos.spec.ts` (solo tramo de distancia); API `publicaciones.e2e-spec.ts` «ninguna respuesta a un negocio trae nombre, teléfono, coordenadas, barrio ni distancia numérica»; `administracion.e2e-spec.ts` «nunca ubicación ni contraseña»; `privacidad.e2e-spec.ts` (la exportación solo entrega lo propio) |
| R6  | Las publicaciones las ven todos los centros y compradores cercanos, compren o no ese material               | API `publicaciones.e2e-spec.ts` «la ven todos los negocios verificados, compren o no ese material, también lejos»; «"Lo verán N" cuenta a todos los negocios verificados de la ciudad»; BD `tramos.spec.ts`                                                                                                                                                                                                                                                                                                             |
| R7  | Los pagos de las operaciones ocurren fuera de RecicloMap                                                    | API `operaciones.e2e-spec.ts` «el pago ocurre fuera de RecicloMap: no hay campos ni rutas para cobrar»; `plan.e2e-spec.ts` «…sin precios ni cobros»; Flujo `paneles.spec.ts` «…sin pagos ni precios del plan»                                                                                                                                                                                                                                                                                                           |
| R8  | Los desafíos son mensuales                                                                                  | API `juego.e2e-spec.ts` «el progreso sale de los datos reales y la Meta del mes pide 100 kg», «el total acumulado usa los kilos de siempre y el del mes solo los del mes», «pasados 7 días del fin del mes ya no se puede reclamar»; BD `semilla.spec.ts` (una sola Meta del mes); `endurecimiento.spec.ts` «el plazo de reclamo de desafíos solo se corre por lo que el mantenimiento se solapa con él»                                                                                                                |
| R9  | La ruleta es la única mecánica de premios y su resultado se calcula en el servidor                          | U `juego/ruleta.spec.ts` (probabilidad exacta, sin stock, probabilidades mostradas = sorteadas); API `ruleta.e2e-spec.ts` «el resultado sale del servidor, gasta un giro y la respuesta no revela el azar», «cada giro queda auditado», «una ruleta que no suma 100 % se detiene»; `configuracion.e2e-spec.ts` «no guarda si las probabilidades no suman 100 %»; BD `ruleta.spec.ts` (premios solo por giro, estados Ganado → Reclamado → Entregado)                                                                    |
| R10 | Las calificaciones son bidireccionales y solo tras una operación completada                                 | API `operaciones.e2e-spec.ts` «…conforme → calificar» (ambas direcciones) y «no se califica antes de completar»; BD `unicidad.spec.ts` «una calificación por autor y operación»; Flujo `operaciones.spec.ts` «ambos califican»                                                                                                                                                                                                                                                                                          |

## 2. Decisiones críticas del producto

| #   | Decisión                                                                                                                          | Pruebas                                                                                                                                                                                                                                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | El plan Pro solo da estadísticas ampliadas, la etiqueta «Destacado · Plan Pro» y una ventaja limitada (500 m) en «Recomendado»    | API `plan.e2e-spec.ts` «cambiar el plan… no cambia su semáforo, su precio ni su demanda», «los demás órdenes ignoran el plan», «en "Recomendado" la ventaja del Pro es limitada»; `paneles.e2e-spec.ts` «semáforo, precio y demanda son idénticos…»; U `mapa/ordenar.spec.ts` |
| D2  | Solo la administración activa Pro, con motivo e historial inmutable                                                               | BD `plan.spec.ts`; API `plan.e2e-spec.ts` «aprueba con fechas…», «activa y desactiva Pro por su cuenta…»                                                                                                                                                                      |
| D3  | Vencimiento del plan por fechas en hora de Lima, sin depender de una tarea                                                        | API `plan.e2e-spec.ts` «el último día del plan sigue vigente y al día siguiente ya es Gratis»                                                                                                                                                                                 |
| D4  | Los permisos viven en la base de datos, no solo en la API                                                                         | BD `permisos.spec.ts`, `plan.spec.ts`, `administracion.spec.ts`, `endurecimiento.spec.ts`; API `acceso-entre-usuarios.e2e-spec.ts` (matriz de rutas por rol)                                                                                                                  |
| D5  | Toda acción de administración deja su constancia con motivo en la misma transacción                                               | BD `administracion.spec.ts`, `configuracion.spec.ts`, `endurecimiento.spec.ts` «controles operativos»; API `operativo.e2e-spec.ts` «cada cambio queda en la auditoría con su motivo»                                                                                          |
| D6  | Una operación completa entrega puntos, una sola vez (1 punto por kg confirmado)                                                   | BD `juego.spec.ts` «los puntos de una operación son exactamente 1 por kg confirmado»; API `operaciones.e2e-spec.ts`; `juego.e2e-spec.ts`                                                                                                                                      |
| D7  | Los plazos de las operaciones se leen en hora de Lima y no cambian a las operaciones ya creadas                                   | API `confianza.e2e-spec.ts` «la publicación vence a las 168 h y la conformidad se cierra a las 72 h exactas»; `ajustes-12b.e2e-spec.ts`                                                                                                                                       |
| D8  | Una aceptación simultánea deja una sola operación                                                                                 | API `publicaciones.e2e-spec.ts` «dos aceptaciones simultáneas: una gana, la otra recibe 409»                                                                                                                                                                                  |
| D9  | Cuentas suspendidas: no escriben, no aparecen, sus ofertas se retiran                                                             | API `administracion.e2e-spec.ts`; `configuracion.e2e-spec.ts` «con el reciclador suspendido…»; BD `administracion.spec.ts`                                                                                                                                                    |
| D10 | Privacidad: exportar, eliminar con gracia, anonimizar, consentimientos                                                            | BD `privacidad.spec.ts`; API `privacidad.e2e-spec.ts`; Flujo `privacidad.spec.ts`                                                                                                                                                                                             |
| D11 | Seguridad de acceso: bloqueo por intentos, respuestas iguales, CSRF por origen, cookie httpOnly, administración con sesión de 8 h | API `seguridad.e2e-spec.ts`; U `nucleo/configuracion/produccion.spec.ts`; `acceso.e2e-spec.ts`                                                                                                                                                                                |
| D12 | La API se niega a arrancar en producción con datos o claves de ejemplo                                                            | API `seguridad.e2e-spec.ts` «con datos semilla en la base la API se niega a arrancar»; U `produccion.spec.ts`                                                                                                                                                                 |
| D13 | Sin secretos en el repositorio                                                                                                    | U `api/src/seguridad/secretos.spec.ts`                                                                                                                                                                                                                                        |
| D14 | Mantenimiento: solo lectura para todos, los plazos no corren y se devuelven al terminar                                           | BD `endurecimiento.spec.ts` «devolver el tiempo de un mantenimiento a los plazos vigentes»; API `operativo.e2e-spec.ts`; Flujo `operativo-y-sin-conexion.spec.ts` «el mantenimiento deja leer a todos…»                                                                       |
| D15 | La lista del mapa funciona sin Google Maps                                                                                        | Flujo `mapa.spec.ts` «con Maps bloqueado la lista funciona, y Maps se pide después de pintar la lista»                                                                                                                                                                        |
| D16 | Sin conexión se lee lo último guardado, nada se escribe en cola y se borra al cerrar sesión                                       | Flujo `operativo-y-sin-conexion.spec.ts` (sin conexión, botones, cierre de sesión)                                                                                                                                                                                            |
| D17 | Accesibilidad AA y presupuesto de peso en 3G                                                                                      | U `web/src/diseno/contraste.spec.ts`; Flujo `accesibilidad.spec.ts` (axe), `rendimiento.spec.ts` (presupuesto de `presupuesto-peso.json`)                                                                                                                                     |
| D18 | La API está documentada y cada endpoint se prueba en Postman (estado, estructura, reglas y permisos)                              | `pnpm api:postman` (colección en `apps/api/postman`)                                                                                                                                                                                                                          |

## 3. Reglas sin prueba propia

Ninguna regla de las secciones 1 y 2 queda sin prueba automática. La regla R7 no tenía una prueba directa y se agregó
en esta fase. Las deudas de prueba que sí existen (lector de pantalla real, dispositivos reales, Mac) están en
`deuda-tecnica.md`.
